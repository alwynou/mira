# Agent 核心规模验证

<!-- Simplified Chinese documentation is explicitly requested by the user on 2026-09-12. -->

日期：2026-09-14。分支：`codex/agent-core`。本记录承接[质量门槛](QUALITY.md#32-本地性能目标)与[核心验收清单](AGENT_CORE_ACCEPTANCE_TRANSFER.md)，不把小规模机制测试视为产品规模通过。

## 测量边界

设备为 Apple M1 Pro、16 GiB 内存、SSD，系统 macOS 26.6.2（25G83），SwiftPM Release。没有调用 Provider、读取凭据或使用真实对话。旧开发资料不做迁移。

`MiraScaleProbe` 是 `Tests` 下的独立可执行目标，App 只依赖三个正式库，不依赖它。种子经真实 `SessionState.apply`、正文暂存和日志追加写入：每会话 50 个已完成的本地执行、100 条消息，每条可见正文恰 1,024 UTF-8 字节。每个执行另有真实的冻结计划及独立隐藏 replay；不以重复的扩展元数据冒充消息。固定 ID、时间和内容规则可重复生成语料，正文存储生成的物理引用 ID 不要求跨次相同。每会话持久重放必须与种子状态完全相等。

测量路径依次包括文件日志库打开、SQLite 查询投影打开、全部会话游标追赶，以及最新 12 条消息的正文读取；消息内容和顺序必须精确匹配。随后独立测量所选会话的完整状态恢复。`localStoreReady` 是上述读取路径到正文可供展示的合计，**不是只有文件库打开的时间，也不是 App 页面已可操作**。它不包含宿主组装、领域数据库打开、维护／回执恢复、布局或绘制。

每组先运行一次完整投影重建并核对全部消息数，再运行 5 次预热和 30 次正式样本。每次使用新进程；操作系统文件缓存已经预热，不称为磁盘冷缓存。完整投影重建和种子生成另列，不计入常态读取 P95。生成走直接合法批次和持久 reducer，不代表完整 Agent loop 的写入吞吐。退出和进程加载开销另记录在 `processWallMs`；核心路径用 `ContinuousClock`。

## 已定位的开销与实现边界

独立 `sample` 采样捕获 `FileSessionLibrary.load → BackupFileIO.stream → String.init(format:)`：摘要每个字节使用一次通用 `%02x` 格式化。当前修改仅把日志、备份文件流及缓存认证的摘要展示改为固定小写 ASCII 编码。SHA-256／HMAC 算法、摘要文本、完整源字节校验、描述符绑定、目录安全检查及失效正文同步屏障保持原契约。所有 256 个字节及前导零、空输入标准摘要均有一致性断言；文件 I/O 的篡改、符号链接、限额及复制故障测试继续执行。

这一常数开销优化不会解决全库初始化随历史增长的问题。参考语料的十万条消息还会生成 201,000 个正文文件，超过当时 `FileSessionArchive.maximumReferences` 和 `LibraryArchiveLimits.maximumFiles` 的 100,000 上限。必须将启动所有权、按会话读取以及归档限额一起重新核对，不能仅增加数字或跳过损坏检测便宣称完成。

首次执行 Release 的领域基准时，测试入口误入 `MiraCrashProbe` 并以参数错误退出；此时尚未运行领域测试。检查发现该 executable 的对象文件进入了 `MiraKitPackageTests` 链接清单。现已删除 `MiraDataTests` 对 executable 的链接依赖，测试仍使用独立子进程启动探针。新的 Release 链接清单不再包含两种探针的对象文件。这是测试工程修正，没有通过探针检测测试环境后静默返回来掩盖入口冲突。

## 领域参考规模的失败基线

实际 API 写入并核对了 10,000 条记忆、20 个文件和 50,000 个片段，业务 SQLite 为 1,170,903,040 B，知识正文为 204,800,000 B。每类 5 次预热、30 次正式样本；[原始领域 JSON](evidence/agent-domain-scale-initial-20260914.json)保留 240 个样本及从同次测试诊断提取的失败计数。该次测试耗时 261.216 秒，**150 项断言失败**，没有把返回快但无命中的情况算通过。

## 十万消息：核心应用启动配对测量

复用上一节保留的**同一份物理语料**，增加 `MiraScaleProbe runtime`：真实打开文件库和 `AgentApplicationRuntime`，启用实际库访问关口、调度、审批与应用作用域。所有会话包含已结束的真实执行；没有可执行模型、驱动器或工具模块。测试端口统一计数，启动至关闭期间任何工具策略、效果授权、业务／回执、来源授权或维护操作调用都会使测量失败；只允许读取合成维护状态。逐页验证真实会话清单与全部确定性 ID，断言就绪、无待接纳／未结算执行及关闭已结算。

## 十万消息：分块归档与完整恢复

继续使用同一份十万消息／一千会话语料，探针另创建隔离的 `Business.sqlite`，仅包含实际 `library.authority` 与 `business.effects` schema。导出经真实 FileSession 快照、SQLite 只读事务、完整文件复制、独立验证和独占发布；恢复经真实 `SQLiteLibraryRestorer` 的本地准备、会话结算、投影重建及关闭后验证。最后重新打开恢复结果，检查全部会话头、每会话 50 个已完成执行、全部消息页及 **100,000 条可见正文的精确内容和顺序**。隐藏 replay 与计划等其余正文由归档／恢复的全量引用和摘要校验覆盖。来源工厂恰好创建／关闭各一次，任何业务提交或来源授权调用都会使这份已结算本地语料测试失败。

这是单次容量和完整性观察，**不是 P95**，也不等于包含一万记忆／五万知识片段的联合业务库或原生 UI 恢复。后验证为了读取结果会重新生成本地缓存，所以报告中的 `restoredFootprintAfterVerification` 包含重开产生的索引／检查点；原子发布前的严格验证仍排除这些派生文件。脚本仅清理本次拥有的归档输出容器，保留原始合成语料用于后续验收。

## 复现

```sh
swift build --package-path Packages/MiraKit -c release --product MiraScaleProbe
python3 scripts/run_session_scale_measurement.py --sessions 10 100 1000 --output .build/measurements/session-scale.json
```

`--operation runtime --existing-corpus <synthetic-directory>` 只测核心应用启动，显式不执行查询投影重建；默认 `read` 仍执行原有完整重建及读取路径，两种 operation 在报告中分别标识。脚本默认仅删除自己创建的临时目录；`--keep-corpus` 保留合成语料供受控复测，`--existing-corpus` 重用现有合成语料且不会删除它。原始样本保留每阶段耗时、进程 CPU 时间、峰值 RSS、文件数、逻辑字节和分配字节。正式测量期间不并行运行 SwiftPM、Xcode 或其他基准。

领域基准通过真实 Memory 与 Markdown 导入 API 构造 10,000 条记忆及 20 个文件；每文件预检 2,500 个恰 4 KiB 的片段。每类检索单独预热 5 次并采样 30 次，检索后校验来源权限。检索命中与来源校验不等于完整 context contributor／历史选择／assembler 路径，后者需独立补测。
