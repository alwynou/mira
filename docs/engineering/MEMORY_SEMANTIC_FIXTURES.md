# Real-model memory semantic fixtures

`MemoryEmbeddingRuntimeTests` is the focused acceptance gate for the local Qwen 4-bit memory embedding path. It is opt-in because it loads the real MLX model and uses local GPU or unified memory. The test never downloads a model, calls a remote provider, or uses personal conversation data.

Run xcodebuild with `TEST_RUNNER_MIRA_TEST_EMBEDDING_MODEL_DIRECTORY` set (Xcode forwards it to the test process as `MIRA_TEST_EMBEDDING_MODEL_DIRECTORY`) to an already prepared model directory. The suite is serialized and prepares one `MacMemoryEmbeddingService` for the whole acceptance run. It creates a fresh temporary SQLite database, writes synthetic active memories, drains `pendingMemoryIndexJobs` through `completeMemoryIndexJob`, and then calls production `SQLiteMemoryStore.recallMemories`. A second `SQLiteMemoryStore` over the same database is opened without embeddings; its request-scoped `recallMemories` result is the lexical FTS and alias baseline, so the comparison exercises the same privacy and scope filters as production.

The corpus covers a nickname (`Boss`) in equivalent English and Chinese records, food constraints, response structure, work schedule, travel lodging, communication language, commuting, reading, exercise, music, a pet name, lodging budget, meeting hours, outdoor conditions, account security, cuisine, home city, camera equipment, and a Chinese lodging memory. Queries include ordinary paraphrases, ten held-out positive prompts, Chinese-to-English and English-to-Chinese retrieval, close travel distractors, and ten unrelated technical or general subjects.

For each synthetic query the test logs the stable fixture ID, the actual hybrid result IDs, the lexical result IDs, the hybrid top result, and the top three cosine diagnostics from the indexed vectors. Expected IDs are checked by identity rather than by display text. At least five paraphrased positives must be found by hybrid recall while absent from the lexical baseline, and at least three unrelated queries must return no memories. These are acceptance observations for the pinned Qwen space; the test does not change the production similarity floor or tailor the store's synonym expansion.

Chinese literals in the Swift fixture are intentional bilingual test data. They are marked with `i18n-fixture` comments so the language policy checker treats them as test fixtures rather than untranslated product copy.

A failed expected hit below the pinned similarity floor or an ambiguous top neighbor is a model and fixture calibration finding. The logged cosine scores and neighbor IDs are the evidence for reviewing that finding; they do not authorize changing the production floor or adding query-specific aliases. The lexical-lift count only covers cases explicitly marked `provesLexicalMiss`, whose query has no literal fixture term, while ordinary positive and negative results remain separate acceptance evidence.

## 2026-09-18 observed results

The current corpus contains 20 memories and 39 queries. The real pinned model found expected records for 28 of 29 positive prompts; all ten unrelated prompts returned no results. Fourteen expected hybrid hits were absent from the production lexical baseline. Initial calibration logs are `/tmp/mira-memory-semantic-native.log` and `/tmp/mira-memory-semantic-native-final.log`; the complete host acceptance is `/tmp/mira-memory-host-final.log`.

The retained `heldout-communication-zh` case is an explicit Swift Testing known issue: a broad Chinese question about communication style ranks commuting at 0.4106 and misses the stored response-structure preference. It is not counted as a successful recall, and lowering the floor further would not correct the ranking. The focused Chinese reformulation in `communication-focused-zh` retrieves the response-structure memory at 0.6951 with no lexical match. The original broad query remains in the corpus; it was not replaced to manufacture a passing recall rate. `withKnownIssue` will flag an unexpected success so a future model improvement requires reviewing this record.

This model-level gap remains open. Similarity provides candidate context, not evidence for an unstated fact. No query-specific synonym or exception was added to production retrieval. Negative prompts cover unrelated topics; they do not establish universal false-positive rates for adjacent personal topics.
