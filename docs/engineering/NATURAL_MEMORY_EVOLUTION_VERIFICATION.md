# Natural memory activation and evolution verification

Date: 2026-09-07. Branch: `dev`.

This increment changes automatic extraction to version 2. A proposal carries strict assertion metadata: a conservative mode, an optional narrow semantic aspect key, and a change intent. Metadata is advisory and source-bound; it cannot grant scope, disclosure, sensitivity, or replacement authority. A direct automatic activation requires a committed user message quoted byte-for-byte, a stable high-confidence standard user preference or constraint, and a valid aspect key. Ordinary same-kind assertions with different aspect keys can coexist. Automatic replacement is limited to an explicit source change cue, the exact same scope/subject/kind/privacy tuple, and an existing extractor-observed user memory. User-confirmed memories always require review for replacement.

The normalized `memory_assertion_metadata` table binds the assertion to the memory revision, source message revision, and source hash. A later user edit makes the old annotation ineligible for automatic replacement while still allowing it to flag a same-aspect proposal for review. Forgetting clears the classification and body-derived hash in the same transaction and retains only the purge marker. Source text and user-visible memory content remain governed by the existing memory privacy contract.

The retained 32-case EverydayMemory fixture now annotates the 16 expected active cases with test-only metadata. The 16 negative cases intentionally omit that metadata and still exercise questions, reports, temporary statements, sensitive claims, mixed instructions, inferred content, and other optimistic model outputs. The annotations are host expectations for deterministic fixture evaluation; they are not model labels and do not establish Q04 quality.

Deterministic coverage added in `MemoryExtractionValidatorTests` and `MemoryExtractionCommitTests` checks strict version-2 fields, valid aspect-key syntax, exact-source activation, explicit-change cues, unrelated same-kind coexistence, observed-user replacement, manual topic conflicts, metadata revision binding, purge redaction, and review protection for user-confirmed memories. The final integrated package run passed 389 tests in 43 suites. The host EverydayMemory gate passed all 16 authored positives with zero unsafe activations; these remain provisional synthetic labels and do not establish model precision or recall. Those deterministic runs used no provider endpoint or paid model call.

The final integrated package/platform and native results are recorded in [functional milestones verification](FUNCTIONAL_MILESTONES_VERIFICATION.md). Metadata validation now covers historical revision/body consistency, nested aspect-key mirrors and finite purge timestamps. Focused tests cover backup/restore after user revision, purged classifications and malformed metadata. The current development library was recreated at schema 12 without migration or backup.

A single bounded live `deepseek-v4-flash` breakfast scenario then passed automatic activation and natural new-conversation recall with one verified citation, using three provider dispatches under a cap of four. The [synthetic live report](evidence/functional-milestones/live-breakfast.json) and its limits are described in the integrated verification record. Human-labeled Q04–Q06 evaluation and broader real-provider qualification remain open; neither the deterministic fixture rate nor this one-case smoke result is model precision or recall.
