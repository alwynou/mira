## 1. 交付规则

先构建目标核心，再让产品适配它。当前接口或数据库结构兼容性不属于验收标准，正确的产品行为才是。不要通过更换名称、增加包装层来保留现有应用 actor 或大而全的存储接口。

在集成原生宿主之前，先用无 UI 测试组合建立新架构。这是临时的开发安排，不是第二套生产引擎，也不是兼容模式。不得进行生产环境双写，不得保留旧格式读取器、Node 辅助进程或自动回退到旧运行时。最终切换必须移除过时的所有权和权威路径。

P1–P4 优先交付可构建、可测试的无 UI 核心。这些阶段不要求旧原生宿主针对每个中间接口都保持编译通过。如果直接修改接口暂时破坏宿主集成，应记录该事实，并在 P5 完成集成；不要为了让中间版本的应用保持可构建而引入兼容适配器。不要让部分集成的宿主使用开发库运行。

用户于 2026-09-13 明确授权启动 Goal 并创建实施分支，当前使用 `codex/agent-core`。用户再次确认历史数据可直接删除；默认旧开发库已清空，在同一路径保留空目录等待新组合根初始化，不做迁移或备份。按目标架构自主完成实现和验证；确实需要人工参与或外部凭据的检查单独记录并暂缓，不因此阻塞其他工作。iOS 暂不实现。外部消息、付费模型调用及无关操作仍需符合用户实际授权范围。

## 2. 阶段顺序与验收条件

| 阶段 | 交付物 | 依赖 | 验收条件 |
|---|---|---|---|
| P0 | 目标契约、失败矩阵和有界可行性实验 | 本分析 | 日志所有权、删除协议和跨存储协议可以在不削弱保证的前提下实现 |
| P1 | 无 UI 内核、会话状态归约器和有作用域的组合 | P0 | 确定性命令、单一结算路径和扩展隔离可在内存中运行 |
| P2 | 持久化日志、正文数据、恢复和投影 | P0；P1 契约定义 | 真实崩溃/故障测试通过；权威状态可独立于投影重建 |
| P3 | 默认驱动器、Provider/上下文扩展接口、受保护的工具和调度器 | P1；P2 的持久性验收 | 完整的合成 Agent 运行可以跨越取消、审批、重试和重启边界 |
| P4 | 业务模块、回执、来源证据、隐私和备份 | P2、P3 | 现有产品领域运行在新核心上，不依赖 SQL 会话表关联查询或未解决的跨存储缺口 |
| P5 | 一次性宿主切换、数据库结构重建和契约更新 | P4 验收 | 原生产品完全使用新核心，并移除过时的生产路径 |
| P6 | 扩展挑战、完整失败验收和性能测量 | P5 | 核心基线验收通过；之后才恢复新能力扩展 |

在接口固定后，P1 与存储实现可以在各自负责的路径上并行推进；P3 开发期间可以使用内存实现。两者的验收仍取决于真实持久性测试。领域适配不得反过来塑造出向后兼容的内核接口。如果接口有问题，应先修订核心及其测试组合，再引入更多调用方。

## 3. P0 — 契约与可行性实验

交付一组紧凑的契约，为以下内容提供字段定义和可执行示例：

1. 命令 ID、会话/事件序列、批次原子性和不确定追加结果。
2. 执行和调用状态转换、取消竞争、驱动器能力以及强制副作用关口。
3. 类型化扩展注册、生命周期所有权、阶段顺序和失败行为。
4. Provider 准备/续接以及上下文来源契约。
5. 来源引用、授权代次（epoch）、业务回执、待发布回执记录（outbox）和消费者游标。
6. 正文保留组、删除维护和备份快照屏障。

明确回执/待发布记录的关联字段和版本检查、追加通道的已预留/写入中/隔离核对状态、正文发布与租约所有权，以及恢复的跨引用校验顺序。确定并论证适配器的批次/分配上限和文件系统原语。这些都是 P0 的契约交付物，不能留到宿主切换后才发现。

使用合成数据和临时路径运行四项隔离实验：

- 最小日志写入器：首次发布、追加、同步落盘失败、写入器被终止、部分尾部、重复命令、孤儿正文数据、挂起追加的回调重入以及竞争写入器进程。
- 文本/思考草稿流：250 ms / 4 KiB 检查点、结构化续接以及线性有界的存储增长。
- 一次本地业务写入：分别在意图前、意图后、SQLite 回执后和日志结果前崩溃；在变更关口前及业务提交后撤销；证明不会重复写入，也不会让已撤销的回执正文复活。
- 一次遗忘操作：每个阶段崩溃、重启关口、读/备份租约冲突、可见历史保留和隐藏正文删除。

这些是面向生产的原语和契约测试，不是大而无当的临时框架。实验不得安装第二个生产数据库，也不得调用真实 Provider。

**验收条件：**明确每个写入由谁拥有，以及每个边界上的重启行为。如果普通 JSONL 无法满足某项必要保证，应在相同核心契约后面修订其格式或持久化适配器。不要放宽内核，也不要意外让会话 SQLite 投影继续充当权威事实源。如果证据要求改变存储决策，应明确记录该变化。

## 4. P1 — 内核与组合

负责范围：`Packages/MiraKit/Sources/MiraCore` 下新的运行时/会话/组合类型，以及对应的包测试。目录名称可以调整；包依赖方向固定。

工作内容：

- 实现命令校验与确定性状态归约器，覆盖接纳、尝试/工具身份、检查点、取消和终态批次。
- 实现每会话命令通道、用于契约测试的内存 `SessionJournal` 实现，以及受约束的驱动器运行上下文。
- 分离持久事件读取、实时观察和需要按顺序等待的策略阶段。定义游标恢复和订阅者失败行为。
- 实现模块依赖校验、类型化贡献、冻结注册版本和逆序释放。
- 引入应用命令/查询边界，不保留旧 `MiraStore` 的整套方法接口。

**验收条件：**两次竞争接纳、取消与完成的竞争、迟到回调和重复结算都必须只有一个有效结果。失败的模块激活不得泄漏注册项或任务。不同的测试驱动器不能绕过授权、持久化或终态检查。内核测试不得导入 GRDB、UI 或生产 Provider。

## 5. P2 — 持久化会话与读取模型

负责范围：`MiraData` 的日志/正文/投影适配器；只有在证明契约存在缺陷时才修改核心持久化契约；以及聚焦于文件系统和子进程的测试。

工作内容：

- 实现库级写入锁和带有明确同步落盘/发布行为的串行文件系统执行器。
- 实现有界 JSONL 提交批次和可清除的正文引用。明确返回并核对不确定的追加结果。
- 增加草稿分块和思考块检查点；将最终可见内容与隐藏重放保留组分开。
- 实现严格扫描、不完整尾部恢复、游标读取和幂等投影应用。
- 将投影版本/游标与投影行一起保存，并使用已验证的索引，避免普通打开时重放整个库。
- 从权威消息引用构建来源解析器；授权不得读取过期投影。

**验收条件：**在合成库中丢弃全部会话投影，重建后得到相同的历史/轨迹/活动状态，同时不改变业务事实。投影失败不能导致再次分派模型/工具。第二个进程不能成为写入器。已提交的损坏必须明确拒绝继续使用。重试同步落盘失败不能产生第二次接纳。

测量重放时间、检查点延迟、峰值内存、文件数量和写入字节数。分别检查文本流与累计思考流。进程终止覆盖和故障注入不能证明对所有物理断电故障免疫；记录实际使用的同步原语及其支持的保证。

## 6. P3 — 完整的无 UI Agent 执行

负责范围：核心驱动器、Provider 契约、上下文、工具、审批和调度器；`MiraProviders` 适配器注册与现有传输实现；包测试数据。

工作内容：

- 通过内核操作实现迭代式驱动器，冻结路线、注册代次和基础请求。
- 用适配器注册和支持的设置描述符替换 Provider 身份分支。将厂商重放决策移到适配器，同时保留内核资格检查。
- 在符合新契约的地方保留经过验证的 SSE/编码/续接逻辑；将所有 Provider 测试数据更新到该契约。
- 实现结构化上下文贡献和最终校验。先使用合成贡献器；领域模块在 P4 接入。
- 实现完整的工具流程、通用审批、一次性分派、有序的并行结果和互斥屏障。
- 实现跨会话的排队调度、分离的资源租约、活动/审批时钟、有限的符合条件的重试和仅结算重试。

**验收条件：**一个合成会话必须覆盖多个步骤、并行与互斥工具、审批、文本与思考、取消以及最终保存失败。重新打开后必须得到相同的权威状态。驱动器中不得硬编码 Memory/Task/Knowledge 依赖。不得为了让测试数据通过而丢弃 Provider 续接数据。

明确测试不合作的工具：取消反馈要及时，新工作被封锁，迟到的业务提交被拒绝；测试不得声称工具已被强制终止。不需要新增生产工具或 Provider 协议。

## 7. P4 — 领域适配核心

负责范围：核心 Memory/Knowledge/Tasks 用例、领域端口、`SQLiteMemoryStore`、`SQLiteMemoryExtractionStore`、`SQLiteTaskStore`、`SQLiteKnowledgeStore`、journal 精确来源证据、库维护/备份适配器和集成测试。

工作内容：

- 将现有能力注册为 Memory、Knowledge 和 Task 模块。把召回/预取移到贡献器，把完成触发的提取移到持久消费者。
- 将权威业务路径中的消息/执行表外键和关联查询替换为来源引用及当前资格证明。保留用于相对任务解释的原始消息时间/时区。
- 在需要时泛化内部业务回执：意图在日志中，变更、唯一回执和待发布回执记录在 SQLite 中，日志结算来自回执。不要构建通用分布式事务框架。
- 在领域事务中保留记忆决定、抑制规则和作业用量核算、任务变更和通知期望状态事实。投影重建不得重新运行提取或重新创建副作用。
- 实现持久隐私维护、授权代次检查、传递性历史排除、删除受管正文文件和缓存失效。
- 实现库维护屏障、日志/SQLite/正文备份清单，以及带有中断/暂停语义的分阶段恢复。

**验收条件：**通过新的无 UI 组装测试显式记忆保存、自动捕获、新会话召回、替换、遗忘、知识读取/撤销、任务创建和本地提醒期望状态。在每个跨存储边界执行终止/重新打开。领域不得依赖会话投影是否存在或是否最新来执行授权。

备份/恢复和遗忘是宿主切换前的必需项。一个大致可用的会话循环不能替代这一阶段。

## 8. P5 — 直接原生宿主切换

新宿主的[资料库与工作组组装](../architecture/MAC_LIBRARY_COMPOSITION.md)已完成独立组合验证：真实默认驱动器／任务工具、持久恢复、后台工作组排空、维护／导出后重建和通知命名空间隔离均已覆盖。`AppContainer`、展示层、查询／设置服务与恢复激活入口已直接替换，完整 App 和改写后的宿主测试已通过。[历史记忆状态查询](../architecture/AGENT_MEMORY_HISTORY.md)及宿主业务提交后的提示刷新已接通。完整原生交互、规模测量及承接清单中尚未关闭的行为仍继续验收；构建和独立组合通过不等于 P5 已全部完成。

负责范围：`Apps/MiraMac/Composition`、面向应用的命令/查询、展示模型、受影响的本地化/平台测试、当前数据库结构创建和所属文档。

工作内容：

- 在宿主中组合新的运行时、适配器和领域模块。展示层通过新 API 订阅实时快照和持久读取模型。
- 直接替换旧的应用/存储调用方。移除旧循环、旧的会话权威变更、过时的 SQL 表结构，以及不再需要的临时测试组合重复代码。
- 按现有授权，在同一路径重建已确定的开发库前停止受影响的 Mira 实例。此次开发切换不得创建旧格式读取器、保留版本化库或备份副本。源代码、设计资源和 Keychain 凭据不属于清理范围。
- 同步更新当前契约和贡献者说明。保留既有的会话、设置、思考、引用、取消和阅读状态行为；不捆绑 UI 重设计。

## 9. P6 — 证明核心可扩展且可靠

六类[公开扩展挑战](AGENT_CORE_EXTENSION_CHALLENGE.md)已用独立工具、来源模块、提供方、持久观察者、驱动器和作用域任务完成验证；只新增测试自身实现与组装，没有修改循环、会话归约器或生产目录。另已通过[16 个真实进程终止场景](AGENT_PROCESS_CRASH_VERIFICATION.md)，覆盖接纳、思考草稿、日志、业务回执、终态和隐私删除，并在两个后续新进程中验证恢复与幂等性。剩余失败边界和规模测量仍待完成。

不要根据构建成功或协议数量宣布完成。执行提案中的扩展挑战：新增测试工具、贡献器、Provider 家族、持久观察器、驱动器和可释放模块。记录为此需要修改哪些文件。普通扩展若要求修改循环/状态归约器，则属于架构验收失败，必须解释或修正。

使用合成数据运行以下失败矩阵：

| 边界 | 必须达到的结果 |
|---|---|
| 两个窗口同时发送；不确定确认后的重复命令 | 一次接纳和一个非终态执行 |
| 初始正文、日志追加或终态批次期间崩溃 | 不暴露半个批次；重新打开后解决原命令 |
| 磁盘已满、同步失败、尾部格式错误、完整损坏、序列间隙 | 明确拒绝或核对；未提交前置条件时不得产生副作用 |
| 流中断、UTF-8 分片、仅有思考输出的响应、迟到增量 | 恢复最新持久草稿；保留 Provider 内容；忽略过期回调 |
| 工具拒绝、审批过期/重启、策略撤销、输出溢出 | 一个类型明确的终态结果；不得绕过授权 |
| 分派前、并行批次期间、本地提交期间、结算期间取消 | 不产生新副作用；保留已提交业务回执；未知外部结果保持明确 |
| 业务提交后、会话结果/待发布回执确认前崩溃 | 只核对并补齐已有回执；绝不再次执行写入逻辑 |
| 反复重建投影或重放完成消费者 | 读取模型相同；不重复创建记忆/任务/作业；不自动分派网络请求 |
| 工具执行/提取期间遗忘；删除期间崩溃 | 旧授权代次不能提交；启动时继续清理；隐藏正文消失；允许保留的历史仍保留 |
| 工作进行中执行备份；恢复不一致或被篡改的包 | 等待写入静止或拒绝；验证一组一致的前缀、回执链接和正文集合；失败的暂存不能替换当前资料库；恢复保持暂停 |
| 模块激活失败、释放、重复注册、慢观察器 | 确定性失败；没有泄漏的作用域；持久消费者通过游标恢复 |

在能揭示真实边界的地方，使用确定性的调度屏障和子进程终止。避免只重复实现陈述或依赖任意睡眠时长制造的竞态的测试。

### 验证命令

每次修改运行聚焦的测试套件，在集成边界运行包测试套件和应用检查：

```sh
swift test --package-path Packages/MiraKit
xcodebuild -project Mira.xcodeproj -scheme MiraCompositionTests -configuration Debug -destination 'platform=macOS' -derivedDataPath .build/xcode -onlyUsePackageVersionsFromResolvedFile CODE_SIGNING_ALLOWED=NO test
xcodebuild -project Mira.xcodeproj -scheme Mira -configuration Debug -destination 'platform=macOS' -derivedDataPath .build/xcode -onlyUsePackageVersionsFromResolvedFile CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Mira.xcodeproj -scheme Mira -configuration Debug -destination 'platform=macOS' -derivedDataPath .build/xcode -onlyUsePackageVersionsFromResolvedFile CODE_SIGNING_ALLOWED=NO -only-testing:MiraHostTests test
```

如果目标或文件变更影响工程，使用 `xcodegen generate` 重新生成。涉及本地化变更时运行 `python3 scripts/check_language_policy.py`。原生集成必须覆盖浅色/深色、最小窗口尺寸、英文/中文、思考、引用、审批、取消、恢复的草稿、会话切换和阅读位置，并使用合成数据。不需要在 CI 中使用付费端点。在线 Provider 检查需要独立的授权范围和证据。

### 性能与证据

现有 [质量门槛](QUALITY.md#quality-gates) 仍是性能依据：冷启动 P95 不超过 3 秒，召回/上下文 P95 不超过 300 ms，搜索 P95 不超过 500 ms，不得有可复现的连续 100 ms 以上主线程阻塞，本地取消反馈不超过 200 ms。这些是目标，不是对提议系统的测量结果。

在切换前后使用相同的种子测试数据和硬件，对指定分布至少运行 30 次。保留当前 100 条消息的原生回归测试数据，并在文档规定的 100,000 条消息参考规模之前增加以日志为重点的 1,000/10,000 条消息的用例。分别记录存储增长、游标追赶、单会话打开、完整投影重建和峰值内存；完整重建不属于普通启动。

不要凭直觉编造日志延迟阈值。P0/P2 先测量原语，再在最终验收前把有依据的附加验收阈值写入 `QUALITY.md`。即使小型测试数据感觉足够快，检查点的平方级增长、无界订阅者缓冲区和加载整个库的正文仍然是设计失败。

当实现真正运行时，将证据记录到 `docs/engineering/AGENT_CORE_VERIFICATION.md`。列出准确修订、命令、测试数据、数量、环境、测量分布和未验证平台。不得根据更新版本 macOS 上的构建声称 macOS 15 运行时已验收，也不得根据检查 DSH 测试声称 DSH 正确性已验收。

## 10. 范围控制与完成条件

这是覆盖运行时、持久化和领域集成的核心重建，不是小型事件总线重构。等 P0 测量出日志和隐私的复杂度后再估算实施工作；现在给出日历时间会掩盖最重要的不确定性。

在 P6 通过前暂停功能扩展。第一个有价值的实施增量是带故障注入的无 UI 的“接纳 → 模型尝试 → 工具回执 → 助手提交”路径，而不是新 UI 或大型插件目录。尽早安排作用域、游标语义和正文保留；不要把它们推迟到聊天演示可用之后。

当普通能力可以通过文档化扩展接口添加、驱动器中没有领域逻辑、所有跨存储失败边界都有恢复答案、原生产品完全使用新核心，且所需证据已经通过或明确延期并使受影响能力保持不可用时，核心才可继续扩展。其他无关的发布门槛仍单独跟踪。
