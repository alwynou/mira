# 普通回复块上限与重试替换修复

<!-- Chinese engineering evidence follows the user's explicit language preference. -->

日期：2026-09-14。分支：`codex/agent-core`。状态：本次修复与本机验收完成。

## 用户问题与根因

用户向 DeepSeek 提问“你是谁”，普通回复在中途报“模型输出超出块数量上限”；重试后显示两段未完成回答。原生界面读取确认同一个问题下存在两段旧执行的部分正文。

Chat 适配器把每个 `content` delta 都创建为 start／delta／finish 的新块，网络分片数量因此错误地消耗了核心 64 个语义块额度。Thinking 路径则只发布第一次文字快照，后续片段未完整进入可见输出。Anthropic 的 text delta 有同类块身份问题。旧测试分片不足，部分 Thinking 测试还从隐藏续接重建了文字，掩盖了可见流中的遗漏。

用户进一步明确：**重试是重新回答原问题，不保留上一次回答数据**。本次验收按这个行为判断，不能仅在界面隐藏旧回答后宣称完成。

## 流输出修复

- Chat 连续正文／Thinking 使用稳定块身份；内容类型变化才开启另一块，结束、错误或 EOF 清理时刷新尾部。
- Anthropic 保留真实内容块边界和完整 Thinking，工具后的内容按原序发布；截断不发布可运行工具提案。
- 小 delta 有界合并，单个大 delta 拆成同一块的多个追加事件；保留核心 64 块限制及生产者积压上限。
- 测试直接把适配器事件交给 `AgentModelAccumulator`，验证完整文字、思考、顺序与终态；移除从隐藏续接补造可见文字的测试逻辑。

## 重试行为

重试仍绑定原始用户消息，从新执行重新生成，在同一回答位置展示。旧正文、思考、续接和相关生成数据需要由日志记录的替换操作清理；原始问题与执行必要的无正文状态保持可解释。已经提交的工具业务效果不能因为重新回答而被悄悄撤销。

接纳与 `retryCleared` 在同一日志批次提交，清理集合由核心按该问题的全部旧执行和正文所有权验证。生成数据为空也记录清理事实。实际删除失败时保留会话预留与待核对命令，不启动模型；原命令核对成功后才继续。文件库重开从失效集合补完删除，应用恢复只结算已有执行，不重发模型请求。完整契约及流程图见[应用运行时](../architecture/AGENT_APPLICATION_RUNTIME.md)，回答位置与分页见[会话展示层](../architecture/MAC_CONVERSATION_PRESENTATION.md)。

## 已取得证据

- 修复前，160 个 Thinking 片段与 240 个正文片段的 Chat 四种差异规则，以及 Anthropic 分片用例，均复现块数量错误（`/tmp/mira-stream-blocks-before.log`）。
- 修复后实际累加器得到完整的两个 Chat 语义块；Anthropic 保持真实的三个内容块，包含完整签名关联的 Thinking。
- 大片段、正文／Thinking／正文转换、工具前后内容、截断工具抑制、原有网络关闭和错误分类均纳入回归。
- 真实应用运行时的 96 段正文与多段 Thinking 完成、持久化及重开回归通过，不发网络请求、不读取用户凭据。
- 删除故障注入覆盖实际文件库：第一次生成得到部分正文与思考，删除失败后重试命令保持不确定、请求次数不增加；解除故障并核对后生成新回复。另一分支关闭并重开实际应用运行时和文件库，旧文件被清理、排队执行结算为中断，没有自动网络重发。
- 新请求含原问题，不含旧正文和思考；相同重试命令重复提交不增加调用次数。核心归约覆盖清理与接纳的原子性、错误组／遗漏组回滚、禁止分批清理和空生成数据。
- 查询与审计覆盖 `.purged`、原问题与执行计划保留；页面覆盖运行中、成功、失败、无正文终态、重新建立页面、分页与独立问题身份。

## 原生检查

在 macOS 26.6.2 上使用最终 Debug App、`--demo --demo-stress` 和独立临时目录，演示路径不访问用户 Keychain、不发网络请求：

1. 发送合成问题，生成思考和部分 Markdown 后点击停止，出现一条未完成回复。
2. 点击重试后原位置从头生成，只有一个回答，完整输出到 `End of rendering fixture`。
3. 日志确认一个 `cancelled` 终态、一个 `completed` 终态。清理事实覆盖 7 个保留组、117 个旧正文文件，实际剩余旧文件为 0；原始用户消息文件仍存在。
4. 关闭后用同一路径重开，页面展示最新回复和唯一 Thinking 入口，没有重复旧回答。
5. 原生截图检查浅色中文、深色英文与约 852 × 672 的窄窗口；回复和输入区可见，宽表格保留横向滚动。没有改变设计 token。严格的 850 × 620 内容尺寸测量未在本轮确认。
6. 结束并删除该合成目录，恢复中文／随系统偏好，正常资料库重新打开。原始问题、服务商配置与凭据未删除。

本轮原生证据来自当前任务的辅助功能树和窗口截图。收尾阶段 Computer Use 出现窗口变化与 ScreenCaptureKit 错误，重新连接后已确认正常资料库的中文窗口；不将自动化接口异常当作 App 崩溃证据。
