## Selector click-away highlight fix (2026-09-09)

The trigger previously restored focus whenever `isPresented` changed to false. Since trigger focus uses the same background fill as hover, clicking outside the menu closed it but immediately kept the trigger highlighted. The transparent dismissal overlay could also hide a pointer-exit event and leave a stale hover flag.

All close paths now clear hover explicitly. Outside clicks and pointer selection close without restoring trigger focus; Escape, Return, and Space selection restore it for keyboard navigation. Leaving the view clears both states. The unconditional presentation-change focus restoration was removed. The existing self-contained sizing preview documents the click-away versus Escape interaction check, and the design contract reflects the distinction.

The Debug build passed (`.build/settings-select-dismissal/build.log`), and `git diff --check` passed. Mira was restarted with the existing isolated offline demo library. A Chinese/light settings screenshot showed the closed controls with their normal inset fill. Attempts to run an uninterrupted open-and-click-away sequence repeatedly returned CUA's application-changed message, so native reproduction, keyboard regression, and the remaining appearance matrix are not claimed as passes. No host/package-suite or language-policy rerun was performed for this state-only change; no copy, token, target, or provider behavior changed.
