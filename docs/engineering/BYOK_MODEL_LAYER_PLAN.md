# BYOK 服务商与模型层实施计划

日期：2026-09-14。状态：**P0–P6 批准范围已完成**。目标契约见[重设计提案](../architecture/BYOK_MODEL_LAYER_PROPOSAL.md)。用户已授权在 `codex/agent-core` 直接完成核心、协议、存储和 macOS 调用方的重写；实际证据及未验证范围见[验收记录](BYOK_MODEL_LAYER_VERIFICATION.md)。

## 范围与原则

- 官方发现的新模型可直接展示并加入模型池；不以缺少内置条目或未做探测为理由禁止启用。
- 服务商、连接、模型条目、协议、差异规则、用户预设和会话选择独立建模。
- 不为旧格式、旧 API、旧 ownership 或旧测试结构增加兼容桥。保留并重新验证业务正确性不变量。
- 优先完成现有 Chat/Anthropic 接入重组及完整 OpenAI Responses。Google 原生独立安排，不建立空壳实现；iOS、插件市场、任意脚本注入、云端后端和平台 shell 工具不在范围内。
- 不要求所有模型都进行在线探测，也不依赖付费凭据进行 CI。在线验证是独立自选验收，不能由本计划自动触发。

## 实施顺序

| 阶段 | 交付 | 完成依据 |
|---|---|---|
| P0：契约与失败用例 | 明确模型引用（connectionID + modelID）/调用规格、按字段事实来源、选择失效、执行快照及续接语义；为删除回退和型号绑定问题建立有意义的失败用例 | 边界可测试，旧架构耦合测试已分类；无旧 API 适配层 |
| P1：统一输出与续接 | 有序通用内容块、独立隐藏续接、流输出与草稿、日志归约、正文保留和历史投影成组更新 | 多 thinking/text/tool 块和无可见 thinking 的隐藏状态无损往返，错误/取消/恢复正确 |
| P2：模型领域与存储 | 新连接与端点绑定、模型条目、多个调用规格、预设、失效身份；会话选择写日志；配置与资料修订分离 | 删除模型不回退；启用偏好不依赖探测；并发选择与接纳可核对 |
| P3：协议与差异模块 | 拆除七 family；Chat、Anthropic、Responses 独立实现；现有 DeepSeek/Kimi/OpenRouter 行为以受限策略组合 | 每个协议完成工具往返、Thinking、终态、用量、预算与网络关闭测试 |
| P4：动态资料解析 | 完整发现快照、精确资料关联、字段级来源、用户覆盖、原子目录更新和离线读取 | 新 ID 不要求发版；失败刷新不清空模型；元数据不改道、不改历史 |
| P5：macOS 直接接入 | 重写连接、模型列表、模型池和用途选择；高级调用设置由描述符生成；删除手动 family 常规步骤 | 已知服务商正常流程只需连接、选模型、启用；自定义缺项清楚；无强制探测 |
| P6：收尾与下一增量边界 | 当前格式归档/恢复/隐私、完整回归、中文文档及流程图；记录 Google 和原生验收未完成项 | 独立库往返后模型身份、选择和历史仍正确；明确区分代码测试与在线证据 |

这些是依赖顺序，不代表每一步都维持旧 App 可运行。实现分支可以出现中间构建未完成状态；整合前必须直接接通新调用方，不通过旧实现维持表面可用。Google 接入应在其独立增量中按当时官方协议选型，验证 Interactions 与 generateContent 的具体边界，不能用一个泛化名称掩盖两种协议。

## 模块接口验收

建议以少量公开能力组成模块，而不是每个厂商重新写完整客户端：

- `ProviderDefinitionSource`：声明连接及发现规格。
- `ModelDiscoveryProvider`：返回有完整性标识的列表和有来源的可选资料。
- `ModelMetadataSource`：规范化资料，不拥有凭据或执行权限。
- `ModelInvocationPolicy`：给定模型条目、字段事实和用户偏好，纯解析调用规格与可用控制。
- `ModelProtocolAdapter`：纯准备、流解析、协议续接与错误归一化。

以上名称是设计建议，不要求保留现有类型名。注册仍遵守 module scope、依赖拓扑、失败回滚、快照租约与关闭排空；UI 不导入具体策略枚举。新的通用注册类型必须有实际生产使用者，不能只创建空协议。

## 必须覆盖的验收场景

| 场景 | 预期结果 |
|---|---|
| 官方列表返回完全陌生的 model ID | 原样展示，允许启用；有已支持调用规格和明确限制时直接执行，无内置目录检查和强制探测 |
| 未知 ID 缺上下文上限 | 模型条目和启用偏好可以保存；发送前只报告缺少的限制，不误报下架 |
| 服务商列出图片或 embedding 模型 | 正确显示类型；不能误配置为文字 Agent，限制数字不当作对话预算 |
| 同一 model ID 经直连和网关调用 | 使用各自端点、协议、认证、差异规则和价格；不按模型名称复制厂商行为 |
| 同一模型有两个 API 格式 | 可注册两个规格并明确选择；错误不触发另一协议的隐式请求 |
| 新型号只增加数据字段 | 不改核心循环即可配置已有模式；不依赖前缀猜测才能启用 |
| 资料称支持但客户端缺少协议 | 条目仍可见；准确提示缺少协议实现，不以通用 Chat 或关闭 thinking 冒充支持 |
| 删除/禁用当前模型或连接 | 历史可读，显式选择保持失效，不落到工作区或全局默认模型 |
| 用户明确改选或恢复继承 | 日志记录实际意图；稳定命令 ID 去重，后续执行使用新选择 |
| 首次选择与首次发送中途失败 | 用户消息、选择变化和执行接纳符合确定的原子批次规则，无半份会话事实 |
| 更新目录时正在执行工具循环 | 当前快照和价格不变，下一次执行使用新资料；凭据撤销仍能阻止后续派发 |
| 发现第二页超时或取消 | 不发布半份权威列表，不把未读模型标记为删除；任务和传输实际排空 |
| 认证、额度、429、网络、含糊 404 | 分别诊断，不一律变成“不支持/模型下架”，不跨模型重试 |
| 测试在连接或参数修改后迟到 | 旧证据不能写入新规格；失败网络请求不能证明能力不支持 |
| DeepSeek Thinking + 多次工具调用 | 完整 reasoning 和工具历史准确续接；缺失必需历史不能补空值掩盖 |
| Anthropic 多个有序内容块 | 原始 signed/redacted 块与工具配对保持；修改签名前缀明确拒绝 |
| Responses 无可见摘要但有加密状态 | 隐藏状态持久化并正确回放，UI 不伪造 thinking；完整 function 往返 |
| EOF、重复终态、半截工具参数、取消 | 不产生错误成功终态或执行未完成工具，保留可恢复草稿并排空资源 |
| 跨模型、协议、连接及隐私清理 | 不泄漏隐藏续接；可移植内容保留，失效依赖不重新进入模型上下文 |
| 远程元数据含地址、header/body 指令 | 不覆盖已配置请求目的地，不携带用户密钥，不执行代码 |
| 当前格式导出与独立恢复 | 选择、失效身份、资料依据和历史快照一致；不依赖原 App 缓存或远端状态 |
| 扩展挑战 | 注册新同协议服务商仅增加定义/差异配置及必要资料；新增协议不增加厂商分支到默认循环 |

其中旧删除回退场景来自调整前静态分析；新实现已加入删除／禁用不回退、删除后重建身份和会话选择原子性的回归，不把旧版本静态分析记成运行时复现。

## 原生与集成检查

完成 P5 后再执行原生矩阵：内置服务商、新发现模型、自定义连接、资料缺项、无网络、取消发现、模型改选、连接删除、目录刷新和资料库切换。使用合成数据覆盖中文/英文、浅色/深色、最小窗口和键盘操作；遵守现有设计系统。尚未进行的在线或平台检查明确列出。

成组实现后运行包测试、宿主测试和 App 构建；改动文件/target 后重生成工程；涉及 UI 文案时运行语言检查。测试优先验证行为与失败边界，不能仅断言类名、旧 schema 或复制实现细节。通过且代码未变的验证不为凑数量反复执行。

## 数据切换与交付

只有实际实施需要改变格式时，才停止受影响 Mira 实例，按已授权范围删除识别出的开发运行库并在同路径重建；不备份、不保留旧格式读取桥。Keychain 凭据与开发数据是不同资源，不因删除旧资料库而自动删除系统凭据。

修改真实契约时同步更新 `AGENT_MODEL_CONFIGURATION.md`、`AGENT_MODEL_DISCOVERY.md`、`AGENT_HTTP_ADAPTER.md`、`THINKING.md`、`MODEL_CATALOG.md` 及相关宿主/归档文档，清理其中已过期的“宿主尚未切换”描述。阶段证据进入 engineering，进度进入 MVP。完成前不把本提案变为已实现声明。

实施验证与未验证范围记录在[验收记录](BYOK_MODEL_LAYER_VERIFICATION.md)；合成测试、原生检查和真实服务商证据分开陈述。
